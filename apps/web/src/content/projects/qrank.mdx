**QRank** will be a competitive quantum computing platform (under the label Enhanced)
where users solve QC problems and submit code for automatic grading (similar to HackerRank or LeetCode, but quantum).

# What I'm Building

A system that targets containerized execution, microservices, and GPU/cluster backends for fast simulation and ML-assisted tasks.

The main components will include:

- A web app with challenge tracks:
  - **quantum circuits** (OpenQASM/QIR),
  - **variational algorithms** (VQE/QAOA),
  - **quantum annealing**
  - **hybrid computing** (classical optimizer + QPU/simulator).
- A safe, reproducible runner that executes user code in jailed containers and returns structured results (scores, plots, logs).
- A grading pipeline that validates both correctness (state fidelities, energy gaps, constraint checks) and performance (depth, 2-qubit count, wall time).
- A content model for problem statements (MDX) + test bundles (datasets, seeds, reference metrics).

# Platform Highlights

The platform should provide at least the following features:

- **Multi-language**: Python (Qiskit/Cirq/PennyLane/Braket), C++ (QIR/LLVM), and OpenQASM 3.
- **Hybrid kernels**: support for classical loops with measure-feedback; optional access to remote QPUs (future).
- **Artifacts & Replays**: store wavefunction snapshots, counts histograms, and seeds for perfect reproducibility.
- **Leaderboards**: deterministic scoring; tie-breakers on cost function and resource usage.

## Architecture (proposed)

Currently, the architecture is **undecided**, but I am considering the following design:

```text
Web (React/TS, MDX) ─▶ API Gateway ─▶ Job Queue ─▶ Worker Pool (GPU/CPU)
                                │                      ├─ simulators (state-vector, tensor-network, stabilizer)
                                │                      ├─ VQE/QAOA optimizers (Torch/JAX)
                                └─ Auth/Profiles       └─ graders (metrics, constraints, plots)
Storage: Postgres (meta) • MinIO/S3 (artifacts) • Redis (queue/cache) • Loki (logs)
Observability: Prometheus/Grafana • OpenTelemetry
```

**Execution model**:

- User submits solution → API creează job cu test-bundle imuabil.
- Dispatcher alege o imagine runner (ex. qrank-runner:python-qiskit) și planifică pe GPU/CPU.
- Worker rulează testele, emite metrici (fidelity, energy, success prob), artefacte și loguri.
- Grader agregă și scrie scorul final → leaderboard.

## Tech Stack (ideas)

Below I gatherred some technologies that could be used to build QRank (of course these will get probably changed during development
and after a realist analysis of the scaling of the project):

### Frontend

- React + TypeScript (based on Enhanced)
- MDX for problem statements
- Monaco editor for code entry
- WebGL visualizations (Bloch spheres, histograms)
- OAuth2 login

### Backend / Services

- API Gateway: FastAPI or NestJS
- gRPC for service-to-service communication
- Auth: Keycloak (OIDC) or Auth0
- Jobs/Queue: Redis/Arq or RabbitMQ; optional Temporal for durable workflows
- Storage: Postgres (metadata), MinIO/S3 (artifacts), Redis (cache)
- Observability: Prometheus, Grafana, Loki, OpenTelemetry

### Runners / Simulators

- Python images: Qiskit, Cirq, PennyLane (+ Torch/JAX for VQE)
- High-performance simulators: qsim, cuQuantum (state-vector / density-matrix), tensornetwork
- Optional: ingest QIR and pass LLVM to simulators

### Infrastructure

- Docker / Docker Compose for local development
- Kubernetes for scale (NVIDIA GPU Operator)
- Nginx or Traefik ingress, cert-manager, ArgoCD (GitOps)
